---
title: Fine-tuning
description: Build provenance-aware datasets and treat training as one governed improvement target.
---

Fine-tuning is one possible actuator, not the feedback loop itself.

## Decide what should change

- Use retrieval when the answer depends on changing facts.
- Use a deterministic rule or tool when a reliable procedure already exists.
- Improve routing when the wrong model or workflow receives the request.
- Fix the tool schema when arguments or semantics are ambiguous.
- Fine-tune when repeated, well-labeled behavior should be internalized and the expected gain survives holdout evaluation.

## Dataset pipeline

1. Discover recurring failure segments.
2. Require an authoritative corrected answer, label, action, or outcome.
3. Redact secrets and unnecessary personal data.
4. Record consent, provenance, and retention controls.
5. Deduplicate near-identical episodes and templates.
6. Split by entity and time to reduce leakage.
7. Create an immutable dataset manifest.
8. Train through a provider-specific adapter.
9. Create a model candidate for the resulting checkpoint.
10. Evaluate against frozen holdouts, safety, cost, and latency.
11. Register and deploy through the normal candidate lifecycle.

const datasetCandidate = await loop.createCandidateFromFinding({

    schema: "chat-supervised@2",
    records: 1842,
    provenancePolicy: "verified-operator-corrections-only",
    splitPolicy: "entity-and-time-isolated",
  },
  risk: "high",

~~~

## Avoid training contamination

Production transcripts contain noise, secrets, private data, incorrect assistant outputs, operator shorthand, and correlated examples. Do not ingest them wholesale. Maintain source provenance and the ability to remove, expire, or reclassify individual records.

Treat trainer, base model, hyperparameters, dataset manifest, evaluation suite, and resulting checkpoint as independently versioned artifacts.
