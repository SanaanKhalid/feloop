---
title: Improvement candidates
---

A candidate is a proposed artifact change, not an already improved model. Its
`target` identifies a kind/key; `proposedChange` is JSON defined by your adapter.
`risk` defaults to medium. `evidence` records the rationale and versioned manifest;
`metadata` can retain baseline/model/proposer versions and review context.

Creation calculates immutable content (including metadata) and evidence hashes. Reusing a caller ID with
different input fails rather than replacing it. Reconsideration requires an explicit
new candidate identity when evidence, evaluator, model, dataset or proposal changes.
The controller's derived IDs include evidence fingerprint, recipe/version, proposal
and configured evaluator/dataset versions.

The lifecycle is proposed → evaluated → approved → deployed. Failed evaluation stays
evaluated with a failing result; it cannot be approved. Proposed/evaluated/approved
candidates may be rejected. A deployed candidate becomes superseded when a newer one
applies, or rolled_back when reversed. Rolled-back candidates cannot be silently
redeployed. Imported old history lives outside this active lifecycle.

Evaluation snapshots the current revision before calling the evaluator. When it
returns, Loopiter verifies the revision has not changed. A human rejection, a newer
evaluation or approval wins over stale results. Approval requires the exact latest
passing evaluation ID and the same candidate content/evidence. It records the actor
and timestamp; the application must authorize that actor.

Mutable states use compare-and-swap revisions; candidate content cannot be edited in
place. Create a new candidate to change its prompt or evidence. Evaluation versions
and dataset hashes are mandatory strings supplied by your evaluator pipeline: the
SDK cannot verify that a supplied hash honestly describes external data.

Supported target kinds include prompt, routing, rule, retrieval, model, dataset,
threshold, tool_schema, workflow, agent_topology, code, capacity and custom. These are
representation categories, not built-in integrations. Experimental auto-apply is
restricted to low-risk **prompt and routing**; other kinds remain available for
recommendation, evaluation and explicit manual deployment with suitable adapters.
