---
title: Executions and episodes
---

An execution is a prediction, inference, turn, tool call, retrieval, workflow, agent
step or custom action. Supply stable IDs when delivery can be retried. Record model,
prompt, dataset, router or policy versions in `artifacts` and structured analysis
attributes in `metadata`. JSON must be finite, acyclic and made of plain objects.

An episode groups correlated steps, such as turns in one support ticket. An entity
identifies a customer/device or other repeated source without storing their direct
identity. Parent and child executions must share the same episode; create the parent
first. Each client is bound to one namespace; public record inputs do not accept a
second namespace field.

```typescript
import { FeedbackLoop, InMemoryStore } from 'loopiter';
const loop = new FeedbackLoop({ store: new InMemoryStore(), namespace: 'example/dev' });
const turn = await loop.recordExecution({
  id: 'turn-1', kind: 'turn', episodeId: 'ticket-1', entityId: 'pseudonymous-17',
  input: { text: 'Synthetic request' }, metadata: { task: 'support' },
});
await loop.completeExecution(turn.id, { output: { label: 'other' } }, turn.revision);
await loop.close();
```

Creation is insert-only. An identical retry returns the original row, even if that
execution was later completed; a conflicting retry raises `conflict`. To change
completion/output/metadata, use `completeExecution(id, input, expectedRevision)`.
Concurrent updates at the same revision produce one winner and an explicit conflict.

Use UTC timestamps. Defaults use the client clock. Completion cannot predate start.
Timestamps supplied for historical fixtures remain historical, not claims that the
model executed then. Treat ID/namespace/version strings as operational identifiers
that must not contain secrets. They are not an authorization system.

Several turns sharing an episode are not independent samples. Analysis defaults to
one weighted scoring unit per episode, or per execution without an episode ID.
Executions can be completed later, but revision changes also change evidence
fingerprints so an earlier proposal does not silently acquire new provenance.
