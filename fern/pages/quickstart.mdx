Use Node 22 or 24. Before publication, access to the repository is required:

```sh
git clone https://github.com/SanaanKhalid/feloop.git
cd feloop
npm ci
npm test
npm run starter -- demo
npm run starter -- demo --reject
```

Both demos use a deterministic **simulated provider, not OpenAI**. Metrics are
calculated from predictions against held-out fixtures. The first fixture demo
explicitly approves its candidate, changes a registry-selected prompt and rolls it
back. The second demonstrates a failed gate. Neither is a claimed live-model result.

For a consumer before publication, run `npm pack` in this checkout and install the
generated tarball. After the separate release action, install
`npm install feloop@0.2.0-alpha.1`. Do not assume that version already exists on npm.

## Connect your PostgreSQL database

Install `pg` in the consuming application. Provision the database yourself. Review
`migrations/001-feedback-store.sql`; apply it with a migration identity, not on every
request. The equivalent explicit helper is shown below. Constructors never migrate.

```typescript
import { Pool } from 'pg';
import { FeedbackLoop } from 'feloop';
import { PostgresStore, migratePostgres } from 'feloop/postgres';

const connectionString = process.env.DATABASE_URL;
if (!connectionString) throw new Error('Set DATABASE_URL explicitly.');
const pool = new Pool({ connectionString });
await migratePostgres(pool);
const loop = new FeedbackLoop({ store: new PostgresStore(pool), namespace: 'support/dev' });
const prediction = await loop.recordExecution({
  id: 'ticket-1-prediction', kind: 'prediction', episodeId: 'ticket-1',
  input: { text: 'Please explain this charge.' }, output: { label: 'other' },
  artifacts: { prompt: 'intent-v1', model: 'your-configured-model' },
});
await loop.recordSignal({
  id: 'ticket-1-review', executionId: prediction.id, kind: 'correction',
  name: 'verified_correct', value: false, correction: { label: 'billing' },
  source: 'authorized-reviewer',
});
await loop.close();
await pool.end();
```

One correction is not enough evidence to propose a change. Collect independent
episodes with verified labels before choosing analysis thresholds.

## Complete live starter

The [classification starter](/get-started/classification-starter) is the complete command runbook (also included in the repository).
Set `DATABASE_URL`, `FELOOP_NAMESPACE`, `OPENAI_API_KEY`, `OPENAI_MODEL` privately.
No default model is guessed. Live model commands require `--live`, send selected
text to OpenAI, may incur charges and default to 80 requests/2,048 output tokens
per request per command. `store:false` is not a zero-retention guarantee.

Run `init --live`, `seed --live`, `recommend --live`, `evaluate --candidate ID --live`,
review the result, then `approve --candidate ID --actor NAME --live` and
`deploy --candidate ID --live`. Each is preceded by `npm run starter --`.
Use `predict --text TEXT --live` to confirm the active registry version is used.
Use `rollback --candidate ID --live` or `reconcile --attempt ID --live` for recovery.

Only the synthetic correction split is seeded automatically. Replace the source
fixture manifest with independently reviewed data before making customer claims;
preserve episode/entity/time isolation and version the evaluator/dataset. Arbitrary
unpartitioned predictions are captured, but are not automatically admitted as training
examples. A live run may return **no candidate passed**; that is a valid result.
